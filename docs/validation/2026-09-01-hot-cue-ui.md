# Hot Cue UI and NVS acceptance

Date: 2026-09-01.

## Scope

Focused DSI eyes-on and FLX4 hardware verification of initial D1/D2 target
visibility and the local Hot Cue overlay. The accepted app-only factory image
was `M3-48-g435bcfe-dirty`, 2,370,992 bytes, SHA-256
`2CDAB5D7C859F28F26E2BB02CDC5B711DA4A25480EA081B18A2C3EF963DF3455`.
Wi-Fi `Pajoniiir-M3` remained enabled throughout the test. The signed
`M3-41-g133f399` rollback baseline in `ota_0` was not modified.

## Implementation

- UI creation now applies the D1/D2 target visual state after all performance
  screens exist, so the selectors do not blend into the background until their
  first touch.
- `deck_core` publishes a bounded UI refresh command only after a successful
  local Hot Cue save or clear.
- Hot Cues cards read the track-scoped `hot_cue_store` overlay and give it
  precedence over immutable Rekordbox ANLZ cue metadata. A deliberately empty
  local overlay remains distinguishable from a track with no local overlay.
- The refresh is processed on the LVGL task; the FLX4 USB callback does not
  call UI code or add per-packet logging.

## Verification

1. The UI simulator first-open regression confirmed visible D1/D2 target
   selectors and rendered a locally created cue without changing tabs. All
   seven screenshot hashes remained at their reviewed baselines.
2. The full P4 host suite passed, including the local-overlay missing/empty
   distinction and refresh-after-queue-flush contracts.
3. ESP-IDF v6.0.2 built the final 2,370,992-byte application successfully;
   flash write and hash verification on COM6 passed.
4. With `Grant Miller - Red For Love...` loaded on D1 (`track_key=7`), physical
   pad A (`0x97/0x00`) created the cue and the card changed from `EMPTY` to its
   time immediately. The status snapshot reported a local mask of `0x01`.
5. D1 Shift + pad A (`0x98/0x00`) cleared the cue and the card returned to
   `EMPTY` immediately; the local mask became `0x00`.
6. A new cue was set at a nonzero playback position. Pressing pad A later made
   the waveform and counter jump immediately to the displayed cue time and
   playback continued cleanly.
7. After flashing/rebooting the final image and reloading the same track, cue A
   appeared without being set again, confirming track-scoped NVS persistence.

A temporary bounded raw-MIDI status probe established that an earlier
`0x96/0x46` event was the D1 LOAD button, not a missing Hot Cue packet. The
probe was removed before the final build so production retains the original
real-time MIDI callback cost.

## Decision

Accept the focused D1 Hot Cue UI/NVS set, clear, recall and reboot/reload gate,
plus initial D1/D2 target visibility. This does not claim a new exhaustive
physical pass of every Hot Cue slot on both decks; the older full pad mapping
and shifted LED results remain recorded in the MIDI acceptance ledger.
Remaining UI work is the Settings eyes-on pass and reviewed 800x480 screenshot
baseline, followed by the prolonged cold-power/reconnect integration soak.
